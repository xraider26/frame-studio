# Orchestra 0.3.1

This maintenance release fixes the MCP connection failure reproduced between a running Windows desktop and packaged Codex, and completes the configuration-copy backlog.

## Changes

- Discover and authenticate to the same desktop even when Codex receives a different AppData view. A per-user connection outside AppData carries a separate, per-launch agent-only credential. Existing project databases and browser/agent credentials remain in place.
- Verify the live service's loopback address, instance, process and data-root identity before using the connection. Reject stale or mismatched records and include the attempted discovery root in connection errors.
- Choose **Codex (TOML)**, **Cursor (JSON)**, **Claude Desktop (JSON)** or **Antigravity (JSON)** from **Orchestra → Copy MCP configuration**. Copied commands use the actual installed resources path and preserve argument boundaries for folders containing spaces.
- Preserve existing image/video workflows, creator calibration and generator safeguards from 0.3.0-beta.1.

## Upgrade

Close Orchestra, install `Orchestra-Setup-0.3.1.exe`, then reopen it. Use the client-specific copy option to replace stale MCP launch entries, and reconnect the MCP client. Existing entries are not silently rewritten. Treat `~/.orchestra/desktop-connections/` as private connection credentials, not an export folder.

The installer remains unsigned. Validation and its limits are recorded in [release verification](../qa/2026-10-25/release-0.3.1.md). Earlier tags and installer assets remain available.
