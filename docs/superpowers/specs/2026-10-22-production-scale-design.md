# Idea-to-production scale and simple controls

User intent: mass-produce quality content from an idea, using their connected agent and generation tools, retaining optional human quality gates. Implement the five requested priorities (batches, consistent identity, quality-driven retries, production queues, proven recipes) and Basic/Professional settings.

## Product contract

- A Production queue workspace starts a batch from an idea and built-in/saved template. Kind is episodes, variations or campaign. Default count 5, bounded 1–100; optional per-item briefs. Each item is an independent existing Studio project with its actual next action, output files, approvals and cost ledger. Idea text is source content for the agent; it is never falsely marked as a completed script or generated media.
- Persist batches and per-project pause/priority, plus durable expiring worker leases. Queue rows distinguish ready work, active agent, waiting on real output, human approval, resource/preflight attention, paused and complete. Agents can claim/renew/finish work through MCP; claims are idempotent and exclusive per project. Human pause/concurrency/budget policy applies to queue and direct generation/provider starts. Existing running provider work can finish.
- Queue task context provides the idea/variant, workflow, actual next action, identity contract, required tools and current revisions. The agent writes real planning outputs, claims actual generation jobs, executes authorized tools and returns real files through existing APIs. No internal LLM, paid provider, NLE or publisher is invented.
- Batch concurrency defaults to 2 projects (1–10). Optional batch budget uses one unit and conservative known planned/actual costs; unknown exposure blocks configured hard caps. Existing per-project budgets and attempts remain enforced. Batch creation is atomic and retry-safe; no partial orphan projects on error.
- Optional canonical identity comes from an existing project's bible and real reference assets. Copy those actual files into each item, track immutable canonical entity definitions/reference mappings and version. Add canonical reference bindings to effective handoffs. Agents may add other entities but cannot silently mutate/remove locked definitions. Human identity updates propagate and reopen affected inputs, preserving unrelated files; refuse propagation during running provider execution. No semantic guarantee that a model respects references is claimed.
- Human-configurable auto quality retry is off by default; bounded retry count defaults to 2. On an inspected selected take with a named defect/failed criterion, record immutable evidence and request a targeted revision. Old assets stay available, dependent outputs reopen, and the next real claim still passes all resource/approval checks. Repeated evidence on an old take cannot consume more retries. Exhaustion surfaces attention; it does not spin or pretend quality passed. The agent/human inspects media; the app does not fabricate vision scores.
- Saved templates are recipes. Show actual usage, costs and observed review defects. Human endorsement records a reviewed pilot/production against matching recipe settings, real selected media and full recorded inspection/checks. Label the precise evidence level with notes/source, rather than asserting universal quality from a saved configuration. Changes to recipe inputs cannot inherit a mismatched endorsement. Existing templates remain usable with no evidence label.
- Basic/Professional modes are local UI preferences for directing, production/defaults and generator settings. Basic reveals essential inputs and retains access to references, quality gates, errors and budgets. Professional exposes all current advanced controls. Switching never edits saved data, discards drafts, suppresses validation or changes agent behavior. Preference survives refresh; existing (?) help remains.

## Implementation decisions

Extend the current FastAPI/SQLite/MCP and Next.js/React app, retain orange/glass, local files and external editing. No new runtime dependencies. Separate modules for production batching/dispatch, identity propagation, recipe evidence and mode controls. All mutations use revision checks and actual API authorization. Human-only policy remains protected even through saved templates or batch creation. Agents use safe default policies when creating batches.

## Verification and boundaries

Test atomic/idempotent batch creation, concurrent leases, pause/direct-claim enforcement, limits/unknown costs, stale revisions, lease recovery, actual shared files/identity version invalidation, finite defect retries and evidence-backed recipe status. DOM tests cover mode persistence/no draft loss and idea-to-queue payloads; run full backend suite/MCP SDK and production builds. Use synthetic actual media for software flow tests; paid/artistic output quality remains unverified. Full-browser verification remains unavailable after the earlier approval-review block unless a separately permitted browser path becomes available; do not retry a blocked launch.

This design implements the user's explicit request; routine decisions above are implementation defaults, not additional claims of user preference. Local rollout into the existing app is authorized; GitHub publication is not inferred.
